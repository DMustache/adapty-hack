# Four retention dashboards: source contract

The offline source is the synthetic Lumen `users.csv.gz` (50,000 users) and `transactions.csv.gz` (29,794 transactions). Both are local, ignored files from the external seed repository; in this workspace they are under `.agent-runtime/offline-data/` and supplied to Compose through `OFFLINE_DATA_DIR`. Import them explicitly; never ship their raw contents or display user IDs in Grafana. A reproducible import records source hashes and replaces one complete snapshot atomically. Grafana reads only through `grafana_ro`.

The four dashboards are **Data and Model Health**, **Business and Revenue**, **Behavior and Segments**, and **Campaign Tracking**. Offline source panels label synthetic historical data. The model inventory panel reports stored prediction source, model ID, version and count; these rows do not prove that the inference service is currently loaded or approved for customers. If no external predictions are stored, it says so explicitly. A stored `ab_test` value describes a user record; it is not proof of assignment, a view, or treatment. The transaction file supports descriptive purchases, refunds and billing issues, but does not establish a causal effect or the external researcher's churn target.

Current filters: install UTC range, platform, country, acquisition channel, onboarding goal, flow and A/B test name. Report segment size with every comparison. Current panels may show counts of users and transaction users, first-day edit and import distributions, purchase/refund/billing-issue counts, and composition by placement/flow/test. Do not call a transaction ratio churn, precision, conversion from exposure or ROI. An empty group shows no data, not zero risk.

The separate Churn Risk Over Time dashboard uses prediction ID, version, source, time, horizon and probability. Counts and risk trends summarize stored outputs; they do not establish accuracy or model coverage. Precision, recall, F1, ROC-AUC, confusion matrix, calibration and concept drift require a frozen target and mature outcomes joined at the original feature cutoff. Feature drift requires versioned feature values and a reference distribution. SHAP requires externally supplied, versioned explanations. Revenue at risk requires a valid next-renewal price and aligned horizon; treatment effect requires randomized assignment and actual exposure/outcome lineage.

Adapty already supplies standard subscription and A/B analytics. Lead first audits available exports and requests a user-provided preset before adding imports. Missing sources are discussed with the user before any mock is designed. A future blind analyst forecast is saved through a separate authenticated form for a fixed segment, horizon and UTC cutoff, before results are revealed; Grafana stays read-only.

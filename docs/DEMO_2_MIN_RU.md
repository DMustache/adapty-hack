# Двухминутное демо: речь, ссылки и команды

Запускайте команды из корня репозитория `/home/dmustache/Work/adapty/adapty-hack`. Нужны Docker Compose, Python 3.12 и свободные локальные порты `8001`, `8002`, `3000`. Демо записывает синтетические прогнозы и симулированные события в локальную БД; запросов на запись в Adapty нет.

## Перед выступлением

```bash
cd /home/dmustache/Work/adapty/adapty-hack
docker compose up --build -d
curl -fsS http://127.0.0.1:8001/health
curl -fsS http://127.0.0.1:8002/health
curl -fsS http://127.0.0.1:3000/api/health
```

Откройте заранее:

- [Data and Model Health](http://127.0.0.1:3000/d/model-health) — панель **Stored prediction sources** показывает число сохранённых прогнозов по источнику и версии; это не оценка качества.
- [Churn Risk Over Time](http://127.0.0.1:3000/d/churn-risk-trajectory) — основной экран живого показа. **Точную ссылку с фильтрами напечатает скрипт** после запуска.
- [Inference API docs](http://127.0.0.1:8001/docs) и [Analytics API docs](http://127.0.0.1:8002/docs) — если понадобится показать маршруты.

Учетные данные Grafana берите из локального `.env` или настроек Compose. Не показывайте файл `.env` на экране.

## Запуск во время показа

В отдельном терминале:

```bash
cd /home/dmustache/Work/adapty/adapty-hack
python scripts/m8_live_demo.py --pause
```

Скрипт сразу печатает `EXPERIMENT:` и `GRAFANA:` и останавливается на стадии `1/7`. Скопируйте **всю** ссылку после `GRAFANA:` в браузер: она задаёт уникальный `app`, источник, версию, выбранного подписчика, диапазон исторических дат и обновление каждые 5 секунд. На каждой остановке дождитесь обновления Grafana и только затем нажимайте Enter в терминале. Новый запуск создаёт отдельный `app_id` и `experiment_id`, поэтому старые прогоны не смешиваются.

| Стадия | Что показать на основном дашборде | Реплика |
| --- | --- | --- |
| `1/7` | Одна точка в **Churn-risk trajectory** | «Получили первую оценку риска для подписчика». |
| `2/7` | Две точки и изменение в **Change in churn risk** | «Повторный срез показывает, как риск изменился». В этом fixture он снижается. |
| `3/7` | Три подписчика в **Current churn probability by subscriber**, изменилось среднее | «Теперь видна группа риска, а не один человек». |
| `4/7` | Панели не меняются; в терминале появляются `PLAN`, контроль и вариант со скидкой 5% | «Это предложение теста и лимит бюджета, ещё не факт назначения или показа». |
| `5/7` | **Simulated A/B lineage events**: три назначения; таблица: `exposure pending` | «Симулируем назначение вариантов». |
| `6/7` | Два показа; две строки: `outcome pending` | «Теперь видно, кому предложение действительно показали». |
| `7/7` | Один исход; одна строка: `mature` | «Появился исход одного продления; остальные записи ещё ожидают исхода». |

Если панели событий пусты, проверьте выбранный диапазон времени и фильтр `source=external`. Здесь `external` означает источник артефакта, **а пользователи и события остаются синтетическими**. Время на оси графика взято из исторического fixture; запись строк и обновление панелей происходят сейчас. Панель **Largest risk changes** после второго среза показывает отрицательное изменение: повторный риск снижается.

## Текст выступления, около двух минут

> Представим сервис с подпиской. Часть пользователей скоро должна продлить её, но может уйти. Для бизнеса важно найти среди них тех, кому стоит предложить скидку, и проверить, поможет ли она удержать подписку. Раздавать скидку всей группе сразу невыгодно: кто-то и так бы остался.
>
> [Открыть ссылку `GRAFANA:`; показать стадии 1–3.] Здесь наша система показывает группу риска. В демо мы создаём синтетических подписчиков и последовательно передаём оценки риска. Сначала появляется одна точка. Затем — второй срез для того же человека: на графике видно изменение риска. Когда добавляются другие подписчики, обновляются список и средний риск группы.
>
> [Показать Data and Model Health.] Мы сохраняем источник, время расчёта, версию и идентификатор каждого прогноза. Так можно проследить, какие данные попали на экран. Сегодня это синтетический показ.
>
> [Стадия 4; показать `PLAN` в терминале.] Следующий шаг — подготовить A/B-тест для выбранной группы. Система предлагает контроль без скидки и вариант с предложением, показывает бюджет и условия окупаемости. Это черновик для бизнеса: скидка никому автоматически не выдаётся.
>
> [Стадии 5–7; показать две последние панели основного дашборда.] Теперь мы симулируем ход теста: сначала назначение вариантов, затем показ предложения, затем исход продления. Счётчики событий растут на дашборде, а таблица отделяет известный исход от тех, которых ещё ждём.
>
> Сегодня исходы заданы сценарием, поэтому они не доказывают эффективность скидки. В рабочем процессе Adapty передавал бы реальные назначения, показы и продления. После A/B-теста бизнес мог бы сравнить результат с контролем и решить, стоит ли расширять предложение на остальных пользователей этой группы риска.

## Проверка после показа

После стадии `7/7` скрипт сохраняет `.agent-runtime/m8-live-demo.json` и печатает итоговые `app_id`, `experiment_id` и ссылку Grafana. Ожидаемые количества: **3 назначения, 2 показа, 1 исход**.

```bash
python -m json.tool .agent-runtime/m8-live-demo.json
```

Если нужно проверить сохранённые события через API, подставьте ID из отчёта:

```bash
curl 'http://127.0.0.1:8002/v1/lineage/<experiment_id>?app_id=<app_id>'
```

Для автоматического прогона без нажатия Enter: `python scripts/m8_live_demo.py --delay-seconds 8`. Три отдельные ситуации A/B/C без пауз: `python scripts/m6_multi_demo.py --output .agent-runtime/m6-demo.json`; их результаты также симулированы.

Подробная карта источников и всех панелей: [SYSTEM_FLOW_AND_DASHBOARDS_RU.md](SYSTEM_FLOW_AND_DASHBOARDS_RU.md). Исходники сценария: [m8_live_demo.py](../scripts/m8_live_demo.py) и [churn-risk-trajectory.json](../grafana/dashboards/churn-risk-trajectory.json).

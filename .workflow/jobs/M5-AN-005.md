# M5-AN-005: Store temporal predictions and expose trajectory reads

Adapt the additive temporal fields and trajectory SQL from `origin/temporal-churn` to current prediction storage. Provide an idempotent migration for both fresh and existing PostgreSQL volumes; never require `docker compose down -v`. Store each distinct `as_of_at` prediction immutably with model/version/source, renewal due time and price; reject conflicting retries. Keep prior v1 rows readable. Expose a scoped trajectory read for service use and read-only Grafana views, partitioned by app, pseudonymous user and model version so changes across versions are not presented as one trajectory. `churn_probability × renewal_price_usd` is expected next-renewal revenue at risk, not observed savings. Acceptance: repeated snapshots, old rows, retry/conflict, migration rerun and read-only grants pass against PostgreSQL.

# M2-QA-001: Economics invariant tests

## Scope
Independently test the frozen M2 contract through `break_even`, `make_plan`, and the HTTP planning endpoint where useful. Cover 10/20/30% thresholds, churn-probability boundaries, infeasible thresholds, zero and tight cent-level budgets, control allocation, assignment completeness/uniqueness, deterministic seed, and no treatment uplift claims. Do not derive tests from the backend worker's implementation.

## Frozen contracts
Refer only to the applicable `contracts/schemas/*.schema.json`. Contact Lead for incompatible assumptions; do not modify shared contracts directly.

## Acceptance
Tests fail if an infeasible discount is allocated, any candidate is omitted/duplicated, exposure overspends, a repeated seeded request changes assignments, or the result claims measured uplift/savings. Verify `no_offer` is used for unallocated candidates and the scenario metadata/disclaimer remain present. No model training or database changes.

## Tests and handoff
Run targeted unit/contract tests and report any expected failures against the current baseline. Commit within worktree. Send Lead commit SHA and create `handoffs/M2-QA-001.md` with modified files, tests and blockers. Lead merges to develop and runs the full gate.

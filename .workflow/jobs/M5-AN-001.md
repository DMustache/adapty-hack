# M5-AN-001: Store joinable learning events

Add versioned, non-destructive storage and ingestion for approved assignment, actual exposure and observed next-renewal outcome, linked by app/pseudonymous user, prediction/model version and experiment/arm IDs. Keep UTC event time and ingest time, event source and idempotency keys. Reject conflicting retries, preserve first immutable records, and represent missing or late exposure/outcome explicitly. Keep existing generic observations and v1 reads compatible. Acceptance: one customer's prediction-to-outcome lineage is queryable; duplicate events do not duplicate rows; an unexposed proposal cannot be labeled as an A/B outcome.

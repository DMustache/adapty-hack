# M3-AN-001: Analytics and persistence

## Scope
Harden the existing analytics service and PostgreSQL schema for immutable prediction and experiment ingestion. For each ID, an equivalent retry returns `duplicate` without changing the stored row; a conflicting retry returns HTTP 409. Compare stable prediction fields (including model/version/source, horizon and probability) while retaining the first `predicted_at`, since inference can regenerate that timestamp on a request retry. Preserve experiment request-fingerprint conflict behavior, make insertion safe under concurrent requests, and keep actual observations in their separate table. Coordinate data-shape needs through Lead; do not edit dashboards.

## Frozen contracts
Refer only to the applicable `contracts/schemas/*.schema.json`. Contact Lead for incompatible assumptions; do not modify shared contracts directly.

## Acceptance
Prediction and experiment IDs cannot silently overwrite or accept conflicting content. Equivalent retries are idempotent, including prediction retries with only a new generated timestamp. Read endpoints return stored provenance and scenario values. PostgreSQL changes, if needed, use a versioned non-destructive migration rather than a volume reset. No fake effect is inferred; Grafana's read-only role retains SELECT-only access.

## Tests and handoff
Run targeted unit/contract tests, including a database-backed check when practical. Commit only owned source and `handoffs/M3-AN-001.md`; send Lead the commit SHA, checks and blockers. Lead merges to develop and runs the full gate.
